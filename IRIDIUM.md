# Iridium — чем этот форк отличается от Zed

Iridium — форк редактора [Zed](https://github.com/zed-industries/zed) (репозиторий
`github.com/pbarovsky/zed`, основная ветка `iridium`). Цель — редактор с низким
потреблением ресурсов Zed и привычным интерфейсом VS Code, без аккаунтов, телеметрии
и фоновой сетевой активности.

Этот файл — главный источник правды о форке. **Любая новая фича или изменение
поведения записывается сюда в том же изменении**, в котором сделана (см. правило в
`.rules`).

Синхронизация с Zed: remote `upstream` (github.com/zed-industries/zed), ветка `main`
вливается в `iridium` (`git fetch upstream main && git merge upstream/main`).
Последнее слияние: 2026-11-10, `upstream/main` = `b1962f7cd8`. При конфликтах приоритет у
изменений форка, улучшения Zed (производительность, исправления) принимаются.

## Принципы

- **Минимум правок в файлах Zed.** Новое пишется в отдельных файлах (модули,
  компоненты), а в файлах Zed — короткие точки подключения. Так проще подтягивать
  свежий Zed и переносить из него новые фичи.
- **Тесты Zed не ломаем.** Если форк меняет поведение по умолчанию, в тестовой
  сборке (`cfg!(test)`) остаётся поведение Zed, раз тесты проверяют именно его.
- **Своё — без переключателя «как в Zed».** Где пользователь выбрал вариант форка
  (вид git-панели, показ изменений по файлу), классического варианта в настройках нет.

## Имя и логотип

Форк переименовывается в Iridium поэтапно. Исходник логотипа (временный) —
`assets/iridium_icon_v1.svg`.

Сделано (этап 1):
- Имя приложения: `ReleaseChannel::display_name` — «Iridium», «Iridium Dev», …
  (заголовок окна, About, уведомления, имя клиента для LSP и агентов).
- Идентификаторы: Wayland app_id / X11 WM_CLASS / bundle id —
  `io.github.pbarovsky.Iridium[-Dev|-Nightly|-Preview]`, Windows —
  `Iridium-Editor-*`. Окна форка больше не группируются с установленным Zed.
- Меню: «About Iridium», «Hide Iridium», «Quit Iridium», меню приложения «Iridium».
- Иконка приложения: `crates/zed/resources/app-icon.svg` (плитка со скруглением и
  логотипом) → `app-icon*.png` (512 и 1024, одинаковые для всех каналов) и
  `windows/app-icon*.ico`. Перерисовать PNG: `ksvgtopng 512 512 <svg> <png>`.
- `.desktop`-шаблон: описание и ключевые слова.
- Каталоги настроек и данных — см. «Заметки для разработки» (`paths::APP_NAME`).

Осталось:
- Бинарник и крейт `zed` (`target/debug/zed`, CLI `zed`), скрипты сборки и установки
  (`script/bundle-*`, `install-linux`), имя `.desktop`-файла, flatpak-манифест
  (CLI проверяет `FLATPAK_ID` на `dev.zed.Zed`).
- Схема ссылок `zed://`, папка проекта `.zed/` (вместе с совместимостью — решить).
- Тексты интерфейса с «Zed» (пункты меню Help: «Zed Repository» и т. п., онбординг,
  описания настроек, сообщения об ошибках), документация.

## Интерфейс

### Activity bar (как в VS Code)
- Файл: `crates/workspace/src/activity_bar.rs`. Иконки Codicons:
  `assets/icons/activity_*.svg`.
- Кнопка на каждую панель левого и правого доков, перетаскивание для смены порядка
  (порядок хранится в БД, ключ `activity_bar_order`), бейджи, шестерёнка с меню
  настроек, тултипы с горячими клавишами.
- Настройки `activity_bar`: `show`, `position` (`left` / `right` / `top` — сверху
  левого дока, высотой с панель вкладок), `icon_size` (только для вертикального бара).
- Если activity bar выключен, те же кнопки (без рамки, как кнопки терминала)
  показываются в начале левой части статус-бара.

### Title bar
- Слева логотип Iridium, за ним меню приложения, как в VS Code (Linux/Windows; на macOS
  меню системное). Одноцветная иконка `assets/icons/iridium_logo.svg`
  (`IconName::IridiumLogo`, тень — полупрозрачностью), цвет `Muted`.
- Меню приложения в одной строке с кнопками окна.
- Справа три кнопки раскладки, как в VS Code: левая боковая панель (левый док),
  нижняя панель (нижний док), боковая панель тредов агента. Иконки
  `assets/icons/layout_*.svg`.
- Нет кнопки входа и меню пользователя (аккаунтов нет).

### Status bar
- Слева только: кнопки панелей (если activity bar выключен), проект, worktree,
  ветка (полное имя, обрезается только при нехватке места) и кнопка
  fetch/push/pull — та же split-кнопка, что в git-панели
  (`git_ui::GitRemoteButton`, `crates/git_ui/src/git_ui.rs`).
- Всё остальное справа. Проект/ветка — `crates/title_bar/src/project_status_item.rs`.
- Настройки показа проекта/ветки перенесены из `title_bar` в `status_bar`:
  `show_project_items`, `show_worktree_name`, `show_branch_name`,
  `show_branch_status_icon` (миграция `crates/migrator/src/migrations/m_2026_11_06`).
- Справа с краю — колокольчик центра уведомлений (см. ниже), рядом индикатор
  «Offline»: горит, пока офлайн-режим включён в настройках (или `--offline`), или
  пока на компьютере нет сети. По клику ничего не переключает.
- Кнопки панелей нижнего дока (терминал, отладчик) — справа.

### Центр уведомлений
- Файл: `crates/workspace/src/notification_center.rs`, архив — в
  `crates/workspace/src/notifications.rs` (`Notifications::closed`).
- Уведомление, закрытое крестиком или Escape, не пропадает, а уходит в центр
  (до 50 штук, на каждое окно). Уведомление, на которое ответили кнопкой
  (Download, Not Now, действия языкового сервера), туда не попадает
  (`mark_notification_answered`).
- Колокольчик в правом углу статус-бара (Codicons-иконки
  `assets/icons/notification_bell*.svg`, с точкой и акцентным цветом, если есть
  уведомления) открывает панель вверх: в ней сами уведомления с их кнопками, крестик
  удаляет уведомление из центра, кнопка «Clear All» — все и закрывает панель.
  Панель закрывается кликом вне неё, Escape или по колокольчику.
- В центре уведомления рисуются плоскими строками без тени и рамки, разделёнными
  тонкой линией (`is_in_notification_center` в `notifications.rs`; так сделано для
  `MessageNotification` и вопросов языковых серверов).
- Вопрос о скачивании, закрытый крестиком, остаётся без ответа, пока на него не
  ответят из центра; удаление из центра — отказ (спросит снова при следующей попытке).

### Вкладки
- Скруглённые «плавающие» вкладки, у активной — рамка
  (`crates/ui/src/components/tab.rs`, `crates/workspace/src/pane.rs`).

### Панель поиска
- Поиск по проекту в боковой панели, как в VS Code (`crates/search/src/search_panel.rs`,
  перенесено из форка Wu). `DeploySearch` открывает её.

### Панель расширений
- Расширения в боковой панели (`crates/extensions_ui/src/extensions_panel.rs`,
  компактный режим `ExtensionsPage` / `ExtensionCard`).
- Каталог с zed.dev загружается только при первом открытии панели.
- У установленного расширения с новой версией вместо «Uninstall» кнопка **Update**;
  «Uninstall» — в меню «…». Обновляются расширения только этой кнопкой, по одному.
- Доступные обновления проверяются (без установки) при запуске и при каждом открытии
  панели (`ExtensionStore::refresh_available_updates`); их число — бейдж на кнопке
  панели в activity bar. Настройка `extensions_panel.show_count_badge` (по умолчанию
  `true`, Settings → Panels → Extensions Update Badge).

## Git

### Git-панель в стиле VS Code
- Файл: `crates/git_ui/src/git_panel/vscode_layout.rs` (подключение — три строки в
  `GitPanel::render`). Классического вида Zed в настройках нет (в тестах — он).
- Сверху поле коммита и кнопка Commit на всю ширину (split-кнопка с меню
  Amend / Signoff / Skip Hooks), под ними View Diff / Stage All / view options и
  список изменений.
- Внизу сворачиваемые секции с изменяемой высотой (тянуть за верхнюю границу):
  **Last Commit** (с Uncommit), **Graph** (встроенный граф текущей ветки, кнопка
  открыть полный граф), **History** (подгрузка по 100 коммитов при прокрутке),
  **Repositories** (все репозитории проекта, клик — сделать активным).
- Раскрытость и высоты секций сохраняются в БД (ключ `git_panel_vscode_layout`).
- Граф и история создаются только при раскрытой секции и делят один кеш git-лога.

### Просмотр изменений по одному файлу (как VS Code)
- Клик по файлу в git-панели открывает `SoloDiffView` с файлом целиком, каждый файл
  в своей вкладке. Режим «весь файл / только изменения» — две кнопки рядом с
  Unified/Split, один на все диффы (настройка `git.file_diff.show_full_file`).
- Кнопки «Stage File» / «Unstage File» (в Zed подписаны «Stage All» / «Unstage All»).
- Настройка `git_panel.entry_primary_click_action` в форке игнорируется и скрыта:
  всегда «каждый файл отдельно» (`crates/git_ui/src/git_panel_settings.rs`).

### Просмотр коммита
- `crates/git_ui/src/commit_files_view.rs`: слева панель деталей в стиле панели
  git graph (аватар, автор, дата, копирование email и SHA, View on GitHub,
  сворачиваемое сообщение, список файлов Tree/Flat), справа выбранный файл целиком
  без заголовка, с «весь файл / только изменения», Unified/Split и «Open File».
- Открывается вместо `CommitView` отовсюду (кроме stash). Буфер и дифф строятся
  только для выбранного файла.

## Приватность и сеть

### Нет аккаунта, телеметрии и collab
- Вход в аккаунт отключён в `Client::sign_in` (кроме тестов), нет кнопок входа,
  провайдер моделей zed.dev не регистрируется, edit predictions по умолчанию `none`.
- Телеметрия и отчёты о падениях выключены в `TelemetrySettings` независимо от
  настроек.
- Collab panel, настройки звонков и звука удалены из интерфейса (крейт `collab_ui`
  в репозитории оставлен ради слияний с Zed, но не подключён).

### Сетевая политика
- **Страж** `crates/http_client/src/network_guard.rs`: через него идут все HTTP-запросы
  Zed. Каждый пишется в лог (`[http_client::network_guard]` в `Iridium.log`, без
  query-строк). Запросы на `localhost` разрешены всегда (локальные модели).
- **Настройки** `network` (Settings → Network → Internet Access):
  - `offline` — офлайн-режим, также `--offline` и `ZED_OFFLINE=1` на сессию.
    Блокирует все запросы и сетевые команды `npm`, не скачивает Node.js; уже
    установленное работает. В статус-баре индикатор. Выключается только в настройках.
  - `ask_before_downloading` (по умолчанию `true`) — перед первой установкой
    языкового сервера, Node.js, npm-пакета агента или расширения, файла
    расширения, prettier, адаптера отладчика — уведомление «Download / Not Now»
    (`crates/zed/src/zed/network.rs`). Ответ «Not Now» помнится до конца сессии;
    закрытие уведомления — тоже «нет», но спросит снова при следующей попытке.
  - `automatic_updates` (по умолчанию `false`) — фоновые проверки и загрузки новых
    версий языковых серверов, агентов, реестра агентов, расширений и их пакетов.
    Выключено: установленное используется как есть.
- **Нет сети на компьютере**: каждые 5 с проверяется, есть ли маршрут в интернет
  (`network_guard::probe_network` — `connect` UDP-сокета, пакеты не отправляются).
  Без сети — индикатор «Offline», вопросы о скачивании не задаются.
- Исключение из «никакой фоновой сети»: проверка доступных обновлений расширений
  при запуске (только список версий с api.zed.dev, ничего не ставится).
- Точки подключения: `lsp_store.rs` (серверы), `node_runtime.rs` (Node.js, `npm`),
  `agent_server_store.rs` и `agent_registry_store.rs` (агенты),
  `extension_host.rs` и `wasm_host/wit/since_v0_8_0.rs` (расширения),
  `prettier_store.rs`, `dap/src/adapters.rs`.
- Проверка: `timeout 90 strace -f -e trace=execve,connect -o /tmp/net.txt target/debug/zed .`
  и посчитать соединения на `:443`, кроме `127.0.0.*` (с настройками по умолчанию
  ожидается только `api.zed.dev/extensions/updates` при запуске).

## Планы и что проверить

- **Центр уведомлений: карточки других видов.** Плоский вид в центре есть только у
  `MessageNotification` и вопросов языковых серверов (`LanguageServerPrompt`).
  Остальные виды уведомлений (например, от агента, об обновлении, ошибки с особым
  интерфейсом) рисуют себя сами с `elevation_3` и в центре будут выглядеть объёмными
  карточками. Проверить, какие ещё уведомления реально попадают в центр, и для них
  тоже учитывать `is_in_notification_center` (или вынести общий вид рамки).
- **Центр уведомлений: ответ кнопкой у других видов.** Только кнопки
  `MessageNotification` и действия `LanguageServerPrompt` вызывают
  `mark_notification_answered`. У других видов уведомлений нажатие кнопки действия
  может положить уведомление в центр, будто его закрыли крестиком. Проверить и
  отметить такие кнопки.

- **Настройки вида коммита из Zed не действуют на просмотр коммита форка.**
  В Zed 1.29 появились `git.commit_view.expand_description` (раскрывать ли описание
  коммита) и `git.commit_view.expand_files` (раскрывать ли файлы), раздел
  Settings → Version Control → Git Commit View. Они работают для `CommitView` Zed, а
  форк открывает свой `CommitFilesView`, где описание сейчас всегда раскрыто
  (`message_collapsed: false`), а файл показывается один. Решить: подключить
  `expand_description` к нашему виду, а `expand_files` скрыть (или оставить как есть).

## Заметки для разработки

- Пользователь пишет по-русски.
- Сборка: `cargo build`, бинарник `target/debug/zed`. Диск маленький: полная debug-сборка
  ~23 ГБ, а `target/debug/incremental` разрастается до 30+ ГБ — удалять его в начале
  каждой задачи, до правок и сборки; при нехватке места — `cargo clean`.
  `cargo test` на крупные крейты обычно не помещается.
- У пользователя бывают открыты свой `target/debug/zed .` и официальный Zed.
  Никогда не завершать процессы по шаблону имени — только запущенные самим собой PID.
- **Свои каталоги**: `paths::APP_NAME = "Iridium"`, поэтому настройки в
  `~/.config/iridium` (settings.json, keymap.json, themes/), данные, расширения,
  языковые серверы, БД и сокет единственного экземпляра — в `~/.local/share/iridium`,
  лог — `~/.local/share/iridium/logs/Iridium.log`, кеш — `~/.cache/iridium`.
  С установленным Zed ничего не общее. Бинарник пока называется `zed`
  (`target/debug/zed`), поэтому проверка «APP_NAME = имя бинарника» из `main.rs` убрана.
- Правило из `.rules`: при изменении исходников первые строки `README.md` —
  баннер `> [!IMPORTANT]`; его не удалять.
